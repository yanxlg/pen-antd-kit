## Pen MCP 生成原型：硬约束与踩坑（实测）
- **execute 只能操作「已在编辑器中打开」的文件**。`filePath` 指向未打开/不存在的文件时，首次 Insert 会成功（文档在内存里），但一旦文档被关闭就**不落盘、直接丢失**（本次生成的 APP 配置管理原型就是这样丢的）。可靠流程：先用 Write 造一个最小合法 `.pen`（`{version:"2.17", themes:{mode:["light","dark"], density:["regular","compact"]}, children:[]}`），让用户在 Pen 里打开它，再用 execute 生成。
- 用户明确要求：**不要在他当前打开的文档上画**（当前活跃编辑器常是 `libraries/antd-6.lib.pen`）。生成前先 `get_app_state` 确认活跃文档，且每个 execute 都显式带 `filePath`。
- **antd 组件是 `type:"script"` 节点**，不是普通节点树，无法用 `descendants` 改内部结构。定制靠 `inputs`（值全是 JSON 字符串）：Table=`{columns, dataSource, scroll, pagination, size, bordered}`，Tree=`{treeData, selectedKeys, defaultExpandAll, showIcon, blockNode, height}`，Tabs=`{items, activeKey}`，Select=`{options:"a|b|c", value, placeholder}`，Input=`{value, placeholder, allowClear}`，Button=`{children, type:"primary"}`，Checkbox=`{checked, children}`，Pagination=`{current,total,pageSize,showSizeChanger}`。各组件支持的 inputs 读 `canvas-components/<Name>.js` 头部 `@input` 注释最准。
- **Table 自带分页**（`pagination` 默认 true），不要再额外插 Pagination，否则视觉重叠。列宽用 `columns[].width`（数字，按比例缩放）。
- **`Update(node,{inputs:{...}})` 是整体替换**：只传 columns 会把 dataSource 清空，必须每次把全部 inputs 重传。
- 属性格式坑：`stroke` 必须带 `type:"color"`；`effect` 不接受 `offsetX/offsetY`；布局枚举是下划线风格（`space_between`，不是 `space-between`）。
- 字体：`Alibaba Sans` 无效会被警告，中文文本用 `Inter` 或直接不指定 fontFamily。
- 性能：整页 `TakeScreenshot`/`Export` 会因 script 组件渲染超时（55–60s）。**按区域逐个截图**（单个组件或单个卡片 frame 都能过）。

## Pen 当前 MCP API 与卡死规律（实测）
- 工具集是 `get_app_state / execute / browser / get_style / read_skill`，不是 batch 那套（`batch_design/batch_get`）；`execute` 里是 `Insert/Copy/Update/Replace/Move/Delete/Get/Print/TakeScreenshot/Export/FindEmptySpace/SetVariables/Generate`，`execute` 和 `browser` 必须带 `filePath`。
- 症状 `you are probably referencing the wrong .pen file`（约 60s 后）＝ **Pen 文档服务被卡住**，不是 filePath 写错。触发条件是重操作：`Get(document, …)` 全文档遍历、整页 `TakeScreenshot`。一旦卡住，之后所有文档类调用都挂起（连 `Print("ping")` 也不行），**只有退出并重启 Pen 才能恢复**；`get_style`/`read_skill` 这类不碰文档的调用仍正常，可用来判断「app 活着还是文档服务挂了」。
- 规避：只做 scoped `Get(nodeId, visitor)`；截图/导出只针对最小节点（单卡片、单抽屉头），结构检查先用 `Get` + `ctx.bounds`；一次验证前先重启 Pen，不要重试超时。
- 用 cua（截图/按键）可以绕过 MCP 观察画布，用来确认 Pen 是否弹窗、卡死或渲染异常。

## 改用「导入公共库」而不是复制组件（standards 0.7.0）

- 机制（`.pen` 格式自带，不是我们发明）：根节点 `imports: { "<别名>": "<路径>" }` + 实例 `{"type":"ref","ref":"<别名>:<组件id>","inputs":{...}}`。32 个本机 `.pen` 里 3 个在用（含交付的 `APP配置运营管理_标准原型_v2.pen`，路径相对该文件）。
- 已实现：`src/library-store.mjs`（`prepareSharedLibrary` 比对 Kit 库 SHA-256，复制 `libraries/antd-6.lib.pen` + `canvas-components/` + `fonts/` + `library.json` 到 `~/.pen`）；CLI `library shared [--force] [--home]`；`doc build` 默认 `--library import`（`--library embed` 保留旧行为，`--refresh-library` 强刷）；`library status` 报 import 别名/路径/是否存在。
- **四条实测规则**（Pen 1.2.13，违反任一条就渲染成默认态或报错）：
  1. `imports` 必须写**绝对路径**——相对路径能渲染组件但会**静默忽略实例 `inputs`**（我一开始就是被这个坑到，三组对照全渲染默认值）；
  2. 只有 `reusable: true` 的库条目能被导入；平台自造的 `antd-icon-live-origin` / `antd-typography-live-origin` 等辅助节点要留在文档里（`Library Anchors`）；
  3. **被导入组件内部 `ref` 的兄弟组件必须在文档里存在**（Table.js 里 `ref:'Y9L6l'` → Pagination；缺失时报 "Component 'Y9L6l' could not be resolved"）；`coreComponents` 那份硬编码清单其实是这个坑的补丁；
  4. **Pen 保存时会删掉导入实例上的 `descendants` 覆盖**（实测：nudge + Cmd+S 后 12 个 ref 只剩 3 个，`descendants` 全被剥离）——所以模板里的槽位覆盖改成把覆盖里的结构 frame **摊平成普通节点**（`flattenInstanceOverrides`），保结构、丢细节，细节损失要记 Notes；要完整保真就用 `--library embed`。
- 顺带修掉一个潜伏 bug：`doc-workspace.mjs` 的 `scriptRefs` 正则要求 `ref` 带引号，而 `canvas-components/*.js` 写的是 `ref:'x'`，导致依赖闭包一直扫不到、只能靠硬编码 `coreComponents` 兜底；改成可选引号后 `buildComponentClosure(['nXLz3'])` 能正确展开出 Pagination/Empty/Spin 等。
- 产物：`~/.pen` 43MB；`examples/prototypes/app-config-admin-shell.pen` 顶层 22 个节点（20 模块 + Plan Notes + Library Anchors），文档 1.34MB（剩下的是模板自身的结构，组件定义不再复制），2167 节点里 ref 全部是 `antd:` 前缀，`descendants` 0 个。
- 验证：`npm test` 44/44（新增 library-store 5 个 + doc-builder 导入/摊平/锚点 3 个）；`standards:validate` 0.7.0 passed。画布实测：100% 缩放下页面 + 抽屉完整渲染（顶栏面包屑/App Source/语言/RTL/头像、筛选区、错误码表格 3 行 + 分页、抽屉内双语 Tab 与手机预览）。

## 公共库目录 `~/.pen` 改为符号链接（修字体加载失败）
- 症状：Pen 报 `Failed to load font 'AlibabaSans' with url 'file:///Users/yanxianliang/.pen/libraries/fonts/ant.design/*.woff2'`。
- 根因：**镜像目录时按 Kit 根去找 `fonts/`，但库的引用是相对库文件自己的**——`fonts/ant.design/*.woff2` 实际在 `<kit>/libraries/fonts/`；`images/**`（370 处引用、70MB）也在 `<kit>/libraries/images/`；只有 `../canvas-components/` 在 Kit 根。第一版 `library shared` 复制了 `<kit>/fonts`（不存在→静默跳过），所以字体全丢，而其它渲染正常。
- 修法：不再复制。`~/.pen/libraries` 与 `~/.pen/canvas-components` 直接 **symlink 到当前 Kit 的对应目录**（`linkOrCopy`，Windows/无链接权限时退回复制），`~/.pen` 从此只有 4KB；`library.json` 记 `manifestVersion: 2` / `assets{mode}` / SHA-256，manifestVersion 变化会强制重建（避免旧布局被判定为最新）。Kit 目录被清理或换版本时，下次 `doc build` 自动重指。
- 结论：库资源不需要"拆分下载"，公共目录必须保持 Kit 的目录结构即可。

## 新规则：原型内容只能由 Pen MCP 生成（standards 0.9.0）
- 新增 `standards/foundations/canvas-write-policy.md`：**设计内容（页面/抽屉/弹窗/面板 Frame、其内部节点、交互态、一切会改变画布外观的修改）一律通过 Pen MCP 生成与更新，禁止用代码读写 `.pen` 产出画面**。唯一例外是 bootstrap——MCP 没有对应操作的部分：创建空文档、写 `imports`、注入库/模板定义（`Library Templates` / `Library Anchors`）、写 `Plan Notes`。MCP 不可用是阻塞，不得降级成写文件交付；`--via file` 仅限测试与排查。
- 实现：`doc build` 默认 `--via mcp`——先把脚手架写进文件（imports + 20 个可复用模板定义 + anchors + notes），再用 `execute` 通过 MCP 创建模块 Frame；`--via file` 保留旧行为供测试。
- 实测踩到两个 Pen 侧事实并已修：① **Pen 1.2.13 不支持全文档 `Get`**（`Get(visit)` / `Get(document, …)` 直接 TypeError），只有 `Get(nodeId, visitor|{depth})` 可用 → 清理旧帧改为读 sidecar `<doc>.instances.json` 里记录的 id、按 id `Delete`；② **实例密集的批次会超 60s 工具预算**（20 个模块一把梭直接超时）→ 拆成每次 3 个模块，`PEN_BATCH_SIZE` 可调。
- 成果：REQ-084 的 **20 个模块 Frame 全部由 MCP 创建成功**（`via: mcp`、`created: 20`、id 记录在 `<doc>.instances.json`）；紧接着 MCP 又卡死（老毛病），所以内容填充与视觉验收仍待做。

## 按用户决定收窄 bootstrap（standards 0.9.1）
- 用户决定：① bootstrap 只写「空文档 + imports」；② 不注入模板，真实需要的内容复制进去再改。
- 实现：`doc build --via mcp`（默认）写空文档 + `imports`（+ 库的 variables/themes），不再注入 `Library Templates` / `Library Anchors` / `Plan Notes`；生成脚本改为 `Insert(document, {type:"ref", ref:"antd:<模板帧id>"})`，占位模块与 `Plan Notes` 也由 MCP 插入；旧帧清理改为按 sidecar 记录的 id **逐个单独 Delete**（Pen 里删除不存在的节点是错误，且错误会让整批回滚，所以每次一个 id 且失败即跳过）。
- **实测到的硬约束（重要）**：`Insert(ref:"antd:<模板帧>")` 成功（外壳 f4rW6H、split-tabs l0UmSc 都能实例化），但 `Replace(<实例>/<槽位路径>, …)` 报 `No such node to replace with path`——**槽位本身就是模板里的 `descendants` 覆盖，Pen 在导入实例上会丢弃它，所以导入模式下"外壳+内容进槽"的嵌套做不到**。三种出路：页面只绑一个模板 / 在 Kit 里做成组合模板（推荐）/ 用 `--library embed`。
- 已处理：`plan validate` 新增 `NESTING_REQUIRES_EMBED`，导入模式下带 `{outer,inner}` 的绑定直接报错并说明三个选项；REQ-084 的 plan 已改成单模板绑定（app-config.workspace → split-tabs，其余三页 → standard-list），assumption 里记下"外壳由 Kit 组合模板或宿主提供"。
- 当前状态：REQ-084 的 .pen 文件 = 空文档 + `imports` + 19 个 variables（还残留冲突测试带进来的 `Screen · 用户管理`，需 MCP Delete）；sidecar ids 为空（上一轮清理后创建失败）。MCP 又卡死（`wrong .pen file` / 连 `Delete` 都超时），需要重启 Pen 才能继续。
- 建议：给 Kit 补"外壳+内容"的组合模板（如 shell+split-tabs、shell+list），这样每个模块都是一次 `Insert(ref:"antd:<组合模板>")`，既符合"不注入"，也保住 App Shell。
