# 状态、反馈与权限

## 1. 状态矩阵

每个主任务先填写状态矩阵，再画高保真页面：

| 阶段 | 必须回答的问题 |
| --- | --- |
| 初始加载 | 用户如何知道系统正在工作？ |
| 正常数据 | 主任务与主行动是否一眼可见？ |
| 空结果 | 是没有业务数据，还是筛选无匹配？下一步是什么？ |
| 请求失败 | 保留了哪些上下文？如何重试？ |
| 编辑 | 哪些值可改、只读或由系统生成？ |
| 校验失败 | 错误在哪里，如何回到首个错误？ |
| 提交中 | 哪些控制被锁定，是否能重复提交或关闭？ |
| 成功 | 用户收到什么反馈，数据何时刷新？ |
| 保存失败 | 输入是否保留，操作何时恢复？ |

不涉及编辑的页面可省略编辑阶段，但加载、数据、查询空和失败是所有数据页面的基线。

## 2. 反馈分工

- Spin/Skeleton：短时加载和结构占位。
- Empty：可解释的空数据或无匹配结果，并给出下一步。
- 表单错误：可修复的字段问题，必须贴近字段。
- Message：短暂的操作成功或无需持续处理的结果。
- Alert/Result：页面级失败、阻断和需要用户明确处理的状态。
- Tooltip：补充说明，不承担关键错误或唯一帮助。

同一个错误只由最接近根因的一层展示一次，避免字段错误、toast 和页面 Alert 同时重复。

## 3. 权限与可用性

- 没有权限的行动隐藏，不展示一个永远不能点击的诱导入口。
- 有权限但因状态暂不可用的行动禁用，并在附近或 tooltip 中解释原因。
- 只读模式与无权限不同：只读数据仍需完整可读，不能用低对比度 disabled 样式替代所有文本。
- 权限过滤先于行动折叠和布局计算。
- 原型注释要标明权限条件和状态条件，不能只画一个“理想管理员”视角。

## 4. 危险与恢复

- 危险动作名称包含对象或结果，例如“停用页面”“删除配置”。
- 确认层显示影响范围；不可逆操作明确说明不可恢复。
- 提交失败后解除锁定、保留用户输入、保留当前筛选和分页（除非业务明确要求重置）。
- 成功刷新失败时，区分“操作已成功”和“列表刷新失败”，避免诱导用户重复执行。
