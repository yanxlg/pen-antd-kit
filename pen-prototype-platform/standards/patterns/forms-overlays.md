# 表单、抽屉与确认流程

## 1. 选择承载方式

- 少量、短字段且不依赖页面上下文：Modal。
- 创建或编辑实体、字段较多、需要保留列表上下文：Drawer。
- 跨步骤、需要大范围比较或主任务本身就是录入：独立页面或工作区。
- 查看模式优先使用可读文本和 Descriptions；编辑模式中不可修改但仍属于表单的数据使用 disabled 控件。

常规编辑抽屉可从 520–600px 起步；复杂多语言或规则编辑可使用 760px；审计表格等宽内容可到 900px。最终宽度由内容决定，正文必须局部滚动，底部行动保持可达。

## 2. 字段结构

- 标签、必填标记、帮助、输入和错误信息职责分离。星号只说明必填，不替代错误提示。
- 同一类表单保持一致的纵向节奏；字段间默认 16–20px，关联字段可组成有标题的分组。
- 选择项支持搜索时明确搜索字段；级联字段变化后，清理已经失效的下游值。
- 字符数、格式、范围和业务限制在输入附近表达，不依赖提交后 toast 才告知。
- 动态规则和多语言内容应提供清楚的当前语言/分组导航、添加删除入口和至少一组真实示例。

## 3. 校验与提交

提交顺序固定为：收集 → 本地校验 → 规范化 → 生成提交快照 → 必要确认 → 锁定交互 → 提交 → 反馈 → 关闭或刷新。

- 校验错误就近显示，并把用户带到第一个错误字段。不要再弹一条重复的通用错误 toast。
- loading 期间锁定关闭、遮罩点击、Esc 和重复提交；失败后恢复编辑能力并保留输入。
- 成功反馈后关闭并刷新来源列表。新建记录是否回第一页必须在原型中明确。
- 关闭含未保存修改的编辑器时，提示“放弃修改 / 继续编辑”。继续编辑是安全的主行动。
- 普通保存不增加泛化确认。发布、发布并启用、批量覆盖或需要查看差异的提交才增加确认步骤。

## 4. 确认层级

- Popconfirm：单行删除、启停和可以用一句话说明影响的快速危险操作。
- Modal：发布前差异、配置快照、冲突、历史详情和不可用一句话解释的影响。
- Drawer：持续编辑或浏览大量同构记录。

确认文案应说明对象、动作和后果；主按钮名称使用实际动作，例如“发布并启用”，不要只写“确定”。危险行动使用 danger 语义。

## 5. 生命周期与冲突

- 打开编辑器时呈现详情加载状态；不要先闪现空表单。
- 关闭后清理临时确认、loading 和选中记录，下一次打开不继承过期状态。
- 服务端版本冲突时停止覆盖，展示已过期状态，并提供重新加载或比较差异的路径。
- 详情加载失败、选项加载失败、保存失败分别表达，不用同一条“系统错误”覆盖全部情况。
