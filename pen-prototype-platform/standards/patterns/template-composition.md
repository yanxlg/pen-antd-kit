# 模板选择与组合

前置步骤：模板绑定之前先完成 `patterns/module-decomposition.md` 的模块清单。模板是给模块用的，不是给需求章节用的；一个模块对应一个 Frame。

## 1. 模板目录是唯一事实源

Kit 构建时由 `libraries/templates.pen` 生成 `registry/templates.json`（schemaVersion ≥ 2）。每个模板记录自带：

- `pattern`、`category`、`capabilities`；
- `summary`：模板自带的描述、适用场景、包含功能、使用方式；
- `declared features`：模板作者在 Sticky Note 上标注的区域；
- `frame`：可复用根节点 id 与 `resolution`；
- `slots`：可替换部分及其 `instruction`；
- `structure`：结构骨架与角色（sider / header / navigation / content / overlay / table / form）；
- `components`：模板已经实例化的组件。

规范不列举模板清单，也不写死模板 id。`pen-antd template list|describe|match` 是唯一入口：新增或改版模板后只要重新构建 Kit，客户端无需修改规范或 CLI。

## 2. 选择流程（强制）

生成任何页面之前必须完成：

1. `pen-antd template describe --all --depth 2` 读全量目录；
2. `pen-antd template match --query "<需求摘要>"` 取候选；
3. 对每个候选执行 `pen-antd template describe --id <id> --depth 3`，读 `use-when`、`includes`、`declared features`、`replaceable parts`、`structure`；
4. 把需求拆成区域：外壳 / 导航 / 筛选 / 列表 / 表单 / 详情 / 覆层；
5. 为每个区域指定模板及使用到的部分，产出组合方案；
6. 按方案实例化，并把方案写入页面 Notes。

只凭模板名字或上一轮经验选模板视为未完成选择流程。

## 3. 组合规则

- **整体优先**：一个模板能覆盖的页面就整体复用，不拆碎重拼。
- **嵌套而非合并**：外壳模板与内容模板共存时，用外壳的内容槽承载内容模板，两者都保持完整。
- **统一桌面分辨率**：Kit 内置页面模板的实际画板及 `resolution` 均为 `1920×1080`。交付页面根节点宽度强制固定为 `1920`，高度至少 `1080`；业务内容更长时保持宽度不变，通过 MCP 增高根节点至完整容纳内容，不得压缩、缩放或裁切内容。嵌套模板的被复用区域填满外壳内容槽（`fill_container`），保留结构与组件并在目标宽度下重排。
- **禁止窄屏状态**：本原型流程不创建、保留或交付 `760px` 等窄屏页面／响应式状态。已有窄屏状态应从交付原型移除；不得以窄屏状态代替默认桌面页面，也不得因页面内容多而改变固定宽度。
- **部分复用**：只用到模板的某个区域（如筛选栏、表格区、抽屉 body）时，复制该模板再删除其余部分，保留被复用区域的结构、间距与组件实例。
- **不重画**：模板已提供的结构从 Kit 复制，不按截图手绘；其中可复用控件保留 library 引用。
- **模板来源**：选定整体模板后，经 MCP 复制为可编辑的普通 Frame。模板名称只是来源标记，必须核对结构、可替换区域和内部组件引用；内层模板复制到外层内容区。
- **默认保留**：模板标注的功能默认全部保留。只有三种情形允许移除：需求显式排除该项、需求说明宿主已提供该项、需求只要求业务内容。“需求没有提到”不构成理由，移除项必须连同依据记在 Notes。
- **初始尺寸**：先按 `1920×1080` 创建桌面页面根节点；内容完成后只允许按实际内容增高，不改变 `1920` 宽度，也不缩放模板。
- **无模板可复用**的区域才用组件自建，并在 Notes 标记为自建。
- **内容区组件引用**：筛选控件、查询/重置按钮、Tabs、Table、分页、表单及状态等，只要当前 Kit 有可复用组件，就使用 `type: "ref"`、`ref: "antd:<组件id>"` 的导入实例。普通 Frame 承担布局或 Kit 没有对应组件的业务内容；`type: "script"`、`scriptUri` 或 `metadata.source` 即使指向 Kit，也不能冒充导入实例。

## 4. 冲突裁定

1. 明确的业务需求与已确认交互；
2. 当前 Kit 的组件能力与 token；
3. 本规范的页面模式与质量要求；
4. 模板示例构图。

模板不能成为缺失状态、权限或异常流程的理由：模板没有的区域不等于页面不需要。

## 5. 实例化约束

- 文档默认**导入库**：`pen-antd doc build` 先把当前 Kit 同步到 `~/.pen`，再写 `imports: { antd: <绝对路径> }`；组件实例用 `antd:<组件id>` 引用，不复制定义。必须用绝对路径，相对路径会静默丢实例覆盖。
- 被导入组件内部引用的兄弟组件（如 Table 内的 Pagination/Empty）与非 `reusable` 的辅助节点要在文档内存在，由 `Library Anchors` 承载。
- 用 MCP 编辑复制后的模板 Frame，通过 `Replace`、`Move` 或 `Update` 填充业务内容；保存重开后回读内容区、组件引用和 import 路径。
- AppShell 内容区中的新库实例先在目标层级试装，并在保存重开后回读。组件配置和容器层级需逐步验证，不能用视觉出现或 MCP 写入成功代替持久化证明。
- 可替换项按其 `instruction` 替换；桌面基准的 Sider 宽度、Header 高度、内容间距和操作顺序保持模板值。需要展示侧栏折叠交互时，仅在固定 1920px 页面内同步调整 Sider 与 Menu 输入，不生成窄屏页面。

## 6. 验收清单

- 生成前已执行 `template describe --all` 与候选 `template describe --id`。
- 需求拆分出的每个区域都能对应到模板部分，或已在 Notes 标记为自建。
- 筛选、列表、Tabs 等每个内容区域都有“模板部分 / 库组件实例 / 无对应组件的业务自建”归属；自建区域逐个回读可复用控件的 `type` 与 `ref`，不能仅凭名称、外观或来源元数据验收。
- 组合方案已写入 Notes：模板 pattern + id、复用部分、替换内容、移除部分及依据。
- 模板已提供的区域没有手绘重建。
- 保存并重开后，每个模板模块的根节点仍为普通 `frame`，结构与当前 Kit 模板相符，嵌套内容仍位于声明的内容区。
- 模板标注的功能齐全；任何被移除项都能对应到需求中的显式说明。
- 页面根节点宽度等于最外层模板 `resolution` 宽度；高度不小于其 `resolution` 高度，并在内容超过基准高度时增高到足以容纳内容。保存重开后检查根节点与内容边界，无缩放、裁切或溢出。
