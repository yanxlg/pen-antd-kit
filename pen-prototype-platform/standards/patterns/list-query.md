# 列表、查询与目录页

## 1. 标准结构

列表页按以下顺序组织：查询区 → 列表卡片工具栏 → 表格 → 分页。业务标题与记录数放在列表卡片左侧，新增等页面级行动放右侧。

查询区和列表卡片是相邻区域，不把查询表单再嵌进列表卡片形成双重边距。目录页嵌入右侧内容时，可移除查询区外层卡片，但保留字段和操作节奏。

## 2. 查询区

- 在固定 `1920px` 桌面页面内使用 24 栅格。普通密度每行 3 项（每项 8 格）；字段较短时每行 4 项（每项 6 格），不另制作窄屏查询状态。
- 首屏通常只展示一行条件。超过一行时提供“展开/收起”，并保留至少一个可见字段。
- 查询与重置按钮尽量位于末行右侧剩余空间；没有空间才换行。
- 输入中的草稿值与已提交查询条件分离。只有点击查询或提交才刷新数据。
- 查询和重置通常回到第一页；重置恢复已定义的初始值，不只是清空可见文本。
- 请求中查询按钮显示 loading，避免重复提交；已有数据是否保留由业务决定，但必须在原型说明。

## 3. 表格与行动

- 使用稳定 row key。服务端分页和客户端分页必须明确，分页总数不能用当前页条数冒充。
- 所有表格的操作列必须位于列定义末尾，并设置 `fixed: "right"`；不因操作数量少或当前页面宽度充足而省略固定配置。
- 操作列必须设置足够的明确宽度，保证按钮、文字行动或“更多”入口不换行、不被裁切。表格宽于容器时配置横向滚动，固定操作列始终可达。
- 名称、代码、模块、操作人等长文本需定义换行或截断策略；截断后必须通过 tooltip、详情或复制获得完整值。
- 状态使用 Badge、Tag 等语义组件并附带文字。
- 行内操作先做权限过滤，再决定是否收入“更多”；不让无权限行动占据折叠名额。
- 删除、启用、停用等单行危险操作使用紧邻触发点的 Popconfirm。只有需要大段差异、影响范围或历史信息时才使用 Modal。
- 表格没有数据时区分“初始无数据”和“查询无结果”；后者应保留或提供清除筛选入口。

## 4. 页面状态

列表原型至少表现以下状态：

1. 初始加载：表格 loading 或骨架，不显示空白页面。
2. 正常数据：使用足够真实的数据暴露列宽问题。
3. 查询无结果：说明是当前条件无匹配，不暗示系统没有任何数据。
4. 请求失败：保留筛选上下文，并提供重试。
5. 行操作进行中：只锁定对应行动或行，不无理由冻结整个页面。
6. 行操作成功：短反馈后刷新；失败恢复操作能力。

## 5. 宽度基线

宽度服务于信息优先级而不是平均分配：短状态列约 90–110px，操作人约 100–120px，时间约 160–180px；名称、代码和说明获得更大空间。以上是构图起点，不覆盖真实内容和翻译长度测试。
