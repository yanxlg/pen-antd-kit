# 页面模板选择与使用

## 1. 通用原则

- 模板用于确定页面结构和交互承载方式，不替代业务信息架构、权限与状态设计。
- Kit 内置页面模板必须从已确认的真实业务页面或交互状态直接导入，再逐步替换为 library 内部组件；不得脱离来源页面自行拼装一个相似页面。
- 导入后替换组件时必须保持来源页面的结构、尺寸、对齐、间距、文案层级和可见状态。组件替换不是重新设计。
- 独立应用先引用 `Frame · Admin App Shell`，再把页面模板放入 `Page Body Slot`；宿主已提供外壳时只使用业务页面模板。
- 模板中的标题、筛选字段、数据列、Tab、目录项和示例数据均为可替换内容；区域层级、主要间距和操作位置作为构图基线保留。
- Ant Design 组件默认不设置 `size`，沿用组件库默认尺寸。只有需求明确要求紧凑密度、特定尺寸，或经确认的受限空间场景，才覆盖 `size`。

## 2. 内置模板来源

当前内置模板来自 `fintechgrowthui` 的真实页面和功能状态：

| 模板 | 页面来源 | 导入状态 |
| --- | --- | --- |
| Standard List Page | `#/error-code` | 错误码管理默认列表 |
| Split Tabs Page | `#/app-config` | APP 配置默认页，包含配置目录和 BFF / 中台 Tabs |
| Drawer Detail | `#/error-code` | 点击错误码编号后打开“查看错误码” |
| Drawer Form | `#/error-code` | 点击“新建错误码”后打开表单抽屉 |

更新模板时应重新打开对应页面和交互状态执行导入，不根据旧截图手工补画。

## 3. Standard List Page · 标准列表页

### 使用场景

用于一个主要数据集的查询、浏览和行级操作，例如配置清单、用户列表、运营记录和任务列表。

### 固定结构

```text
页面标题与说明
├── 页面主行动
├── 查询区
└── 数据表格
    ├── 行级操作
    └── 分页
```

- 页面只保留一个视觉主行动，通常是“新建”。
- 查询区与表格区保持清楚边界，不形成重复卡片和双重内边距。
- 表格列、状态、权限、空态和加载规则继续遵循 `list-query.md`。

## 4. Split Tabs Page · 左右分栏多 Tab

### 使用场景

用于左侧上下文需要持续可见，右侧又包含多个并列工作区的页面，例如应用目录 + 配置类型、组织树 + 成员/权限、模块目录 + 多类资源。

不用于只有少量一次性筛选项的普通列表；这类场景使用标准列表页。

### 固定结构

```text
左右分栏工作区
├── 左侧目录
│   ├── 目录标题与数量
│   ├── 目录搜索
│   └── 当前选中项
└── 右侧内容
    ├── Tabs
    ├── 当前 Tab 工具栏
    └── 当前 Tab 内容
```

- 左侧负责选择持续上下文，右侧 Tabs 负责切换该上下文下的内容类型；两者职责不能互换。
- 切换左侧目录项后，右侧所有 Tab 数据随上下文更新；Tab 的选中状态是否保留由业务明确。
- 目录宽度、响应式与空选择规则遵循 `environment-layout.md` 的“目录 + 内容布局”。

## 5. Drawer Detail · 详情抽屉

### 使用场景

用于在不离开列表或工作区的前提下查看一条记录的只读详情，且详情内容不需要成为独立主任务。

- 内容优先使用 `Descriptions` 或清晰的“标签—值”只读结构，不用 disabled 表单冒充详情。
- 详情加载、失败、无权限和关闭后的焦点返回必须有明确状态。
- 只读详情没有“保存”；需要继续编辑时提供明确的“编辑”入口，并切换到表单抽屉或独立页面。

## 6. Drawer Form · 表单抽屉

### 使用场景

用于新建或编辑实体，需要保留来源列表上下文，且字段数量超过简单 Modal 的承载范围。

- 标题明确表达“新建”或“编辑”及对象名称。
- 表单正文独立滚动，底部操作固定可达；取消在前，提交主行动在后。
- 字段、校验、未保存关闭、提交锁定和成功刷新规则遵循 `forms-overlays.md`。
- 跨步骤、大范围对比或内容宽度明显超过抽屉时，改用独立页面，不继续放大抽屉。

## 7. 模板画布结构

每个模板在 `.pen` 中作为完整父节点组织：

```text
Template · 模板名称
├── Title · 标题
├── Description · 模板描述
├── Scenario · 适用场景
├── Functions · 核心功能
├── Frame · 可复用页面或浮层
├── Association Lines · 关联线与定位点
└── Sticky Notes · 区域说明
```

Sticky Note 只写“区域名称 + 一句话职责”，放在模板右侧并靠近对应目标；关联线使用水平和垂直折线，不使用斜线，不进入实际页面内容。

App Shell 和页面模板在 `Templates & Pages` 中按同一基线横向排列，方便从左到右比较和选用；不要上下堆叠不同模板。

## 8. 选择顺序

1. 先判断是否需要 App Shell。
2. 一个主要数据集选择标准列表页。
3. 持续左侧上下文 + 多内容类型选择左右分栏多 Tab。
4. 只读查看且保留来源上下文选择详情抽屉。
5. 新建或编辑且保留来源上下文选择表单抽屉。
6. 若任务跨步骤、需要大范围比较或抽屉内容过宽，使用独立页面。

## 9. 验收清单

- 使用场景与模板类型匹配，没有用复杂模板承载简单任务。
- 内置模板能够追溯到上表列出的真实页面和操作状态，不是手工模拟页面。
- 页面模板被放入正确宿主环境，没有重复生成 App Shell。
- 同一页面只有一个视觉主行动。
- Tabs、目录、表格、抽屉和表单使用 Kit 内组件。
- 所有表格的操作列位于末尾并设置 `fixed: "right"`，横向滚动时仍保持可达。
- 未在无明确需求时设置 Ant Design 组件 `size`。
- Sticky Note 位于右侧并接近目标，关联线为水平/垂直折线。
- 列表、详情与表单均覆盖必要的加载、失败、空态、权限和提交状态。
