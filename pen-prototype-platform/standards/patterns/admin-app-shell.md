# 后台应用外壳模板

## 1. 适用场景

使用 `Admin App Shell · 后台应用基础布局` 的前提是页面需要完整应用外壳：

- 独立部署的后台管理应用；
- 交付物明确要求同时展示全局导航、应用身份和宿主操作；
- 需要验证侧栏折叠、语言或 RTL 等跨页面能力。

不适用：宿主已经提供外壳、且需求声明只交付业务内容的微前端页面，这时不重复生成 Header、Sider、应用切换和用户入口。

## 1.1 默认沿用规则

本条是 `patterns/template-composition.md` 通用组合规则在外壳上的具体化：模板通过 `pattern=admin-app-shell` 标识自己，选择它之前仍须走通用流程（`template describe --all` → `match` → `describe --id`）。以下只说明选中该模板后的默认行为。

后台管理页面默认复制完整 App Shell 模板为普通 Frame，替换应用身份与导航数据，并在 `Page Body Slot` 填充业务内容；保留 Header、Sider 和 Content 的结构与间距。内部可复用控件使用 library 实例。

## 1.2 页面壳业务数据提取（实例化前必做）

先交叉核对当前 PRD、原始 `.pen` 和同事项的产品页面 HTML；存在 PDF 时也读取其相关页面。区分宿主系统、业务模块、需求／方案标题与文档站点标题，记录每项证据和冲突，再实例化页面壳。不要仅根据文件名、PRD 标题或 HTML 文档站点的品牌栏认定宿主系统名。原始 `.pen` 的重复页面壳标识可作为宿主名称证据；PRD 中“某系统下的模块”可用于确认层级。若证据冲突或仍无法确定，先请用户确认。

| 数据 | 提取与替换规则 |
| --- | --- |
| 宿主系统名 | 使用承载页面的现有系统名称，同时替换左侧品牌区应用名与每页 Breadcrumb 第一级；业务模块名、需求标题不得代替系统名。 |
| 模块名与菜单树 | 按需求的导航层级和交付范围确定模块，再提取其菜单 `items`；详情页、Tab、操作和后续版本功能不自动升为菜单。逐页设置 `selectedKeys`，有父级时设置 `openKeys`。 |
| 页面路径 | Breadcrumb 依次为宿主系统、模块、当前页面／子页面；不能把模板示例路径原样带入，也不能把模块名放在系统层。 |
| 用户显示名 | 原型统一使用 `${宿主系统名}管理员`，替换 Header 的用户名及对应头像文字；不使用“示例用户”或真实个人姓名。 |

宿主系统名、模块名或菜单无法从已确认材料确定时，先标记未核验并向用户确认，不以模板默认值充当业务事实。所有同一模块的页面使用相同宿主系统名、模块名与菜单树；只按当前页改变选中项和面包屑末级。更新复制页面中的可替换节点，保留外壳结构和内部控件引用。

交付页面的顶层节点必须是可编辑的 `type:"frame"`，由当前 Kit 的 App Shell 模板经 MCP 复制而来。名称、`context` 或 `metadata` 不能单独证明模板来源；还需核对 Sider、Header、Content、Page Body 结构及内部 `antd:` 控件引用。模板 id 和区域路径从当前 Kit 读取，不写死在规范中。

模板已经标注的功能默认全部保留：

| 区域 | 默认保留的功能 |
| --- | --- |
| 品牌区 | 应用 Logo、应用名、应用下拉入口 |
| Sider | 应用内 `Menu`（`mode=inline`、`theme=light`）与侧栏折叠 |
| Header 左侧 | 侧栏折叠入口、`Breadcrumb` |
| Header 右侧 | 当地时间、`App Source Switcher`、语言或地区入口、RTL 方向切换、用户头像、用户下拉入口 |

裁剪必须被显式授权，只有以下情况才允许移除对应区域或功能：

1. 需求明确写出“不需要该项”“不提供该项”或等价表述；
2. 需求说明页面运行在宿主外壳内，且宿主已经提供该项，例如微前端只交付业务内容；
3. 需求明确要求只生成业务内容容器。

“需求没有提到某项”不构成移除理由。裁剪后仍必须保留固定项与剩余操作的相对顺序，并在页面 Notes 中记录被移除的项及依据。

## 2. 模板职责

模板画布必须在页面外壳上方提供独立说明区，至少包含：

- 模板名称；
- 适用场景和不适用场景；
- 提供的主要功能；
- “引用模板、替换数据、填充 Page Body Slot、验证状态”的使用流程。

说明区使用与组件章节一致的轻量层级：父节点透明，不增加说明卡背景；标题使用一级标题样式，描述使用次级文字，场景、功能和使用方式以简洁文本节点并列展示，不包装成额外卡片。

模板在 `.pen` 中必须组织为一个完整父节点，而不是散落在 `Templates & Pages` 下的并列对象：

```text
App Shell · 后台应用模板
├── Title · 标题
├── Description · 模板描述
├── Scenario · 适用场景
├── Functions · 核心功能
├── Usage · 使用方式
├── Frame · Admin App Shell
├── Association Lines · 关联线与定位点
└── Sticky Notes · 区域说明
```

复制、移动或发布模板时以 `App Shell · 后台应用模板` 为整体单位；实际页面生成复制其中的 `Frame · Admin App Shell` 结构。

模板提供所有页面共享的固定结构：

| 区域 | 固定规则 | 功能 |
| --- | --- | --- |
| 画板 | 宽 1920px，高至少 1080px | 保持模板桌面宽度；业务内容超出时只增高，不缩放或裁切 |
| Sider Content Slot | 宽 239px，白色背景，原生 slot 容器 | 导航插槽（`slot: []`），可替换应用内导航或自定义 Menu |
| Brand Slot | 高 64px，原生 slot 容器 | 品牌插槽（`slot: []`），展示并允许替换应用 Logo、应用名和应用下拉入口 |
| Header | 高 64px，水平内边距 24px | 承载页面位置和全局操作 |
| Header Flex | 左右分组，左侧 gap 16px，右侧 gap 8px | 保持不同文案长度下的稳定对齐 |
| App Switcher Slot | 原生 slot 容器（`slot: []`） | 切换器插槽，承载应用源或切换 Select 控件 |
| User Profile Slot | 原生 slot 容器（`slot: []`） | 用户信息插槽，承载头像与用户操作菜单 |
| Content | 灰色布局背景，内边距 16px | 表达宿主内容边界 |
| Page Body Slot | 白色、直角、填满剩余区域、原生 slot 容器（`slot: []`） | 页面生成时唯一需要替换的核心业务内容容器 |

## 3. 区域功能

### 3.1 Sider 与菜单

- 品牌区作为 `Brand Slot`（原生 `slot: []`），允许替换应用 Logo、应用名和下拉图标，不改变 64px 高度。
- 侧边栏内容作为 `Sider Content Slot`（原生 `slot: []`），菜单必须使用 Kit 内的 Ant Design `Menu` 实例。
- 页面生成时替换 `items`、`selectedKeys` 和必要的菜单层级；保持 `mode=inline`、`theme=light`。
- 折叠状态必须同步更新 Sider 宽度、`inlineCollapsed` 和折叠图标，不能只隐藏菜单文字。
- 桌面页面固定 1920px 宽；即使展示侧栏折叠交互，页面根节点也不缩窄。同步检查品牌区、Menu 和内容区布局，确保表格与主操作不被 Sider 或画板边缘裁切。

### 3.2 Header 左侧

- 使用 `Layout.Header`，内容必须套一层 `Flex` 组件。
- 左侧依次为侧栏折叠入口和 `Breadcrumb`。
- 面包屑反映当前应用与页面位置；页面生成时替换 `items`，不手绘分隔符。

### 3.3 Header 全局操作区

顺序固定为：

1. 当地时间；
2. `App Source Switcher`；
3. 语言或地区入口；
4. RTL 方向切换；
5. 用户头像；
6. 用户下拉入口。

要求：

- 组件名称统一使用 `App Source Switcher`，不得写成 `App Switcher`。
- 当地时间由运行页面提供动态数据。
- RTL 是独立操作，不与语言切换合并。
- 用户区域包含头像、显示名和下拉入口，生成页面时按 §1.2 的固定格式替换其内容。
- 纯图标入口必须有明确的可访问名称。

### 3.4 内容区域

- `Layout.Content` 外层固定保留 16px 灰色间距，用来区分宿主布局和页面内容容器。
- `Page Body Slot` 使用白色直角容器，不增加圆角、额外卡片边框或第二层同尺寸外边距。
- 生成列表、表单、详情或配置页面时，业务内容只放入 `Page Body Slot`；外壳业务文案按 §1.2 更新实例数据，不重建 Header、Sider 或 Content 间距。

## 4. 可替换项与固定项

可替换：

- Application Logo；
- App Name；
- `Menu.items`、`Menu.selectedKeys` 和菜单层级；
- `Breadcrumb.items`；
- `App Source Switcher` 的 value 与 options；
- 语言、RTL、用户头像和用户名等入口的状态或内容；
- `Page Body Slot`。

固定：

- 1920 × 1080 基准画板；
- 239px Sider；
- 64px Header 和品牌区；
- Header 的 Flex 分组、24px 水平内边距及操作顺序；
- Content 的 16px 外层间距；
- 白色直角内容容器；
- 模板标注的全部外壳功能，按 §1.1 的授权条件才能裁剪。

## 5. 生成流程

1. 默认按完整外壳处理，复制 `Frame · Admin App Shell` 结构；只有需求声明宿主已提供外壳或只交付业务内容时才跳过。
2. 按 §1.2 交叉核对宿主系统、模块、菜单树、页面路径和用户显示名；将各来源及冲突处理记录在计划中。
3. 从当前 Kit 复制 `Admin App Shell · 后台应用基础布局`，不要照着截图重画。
4. 在每个实例中替换品牌区应用名、Menu、Breadcrumb、头像和用户名，并按需求设置 App Source Switcher 数据。
5. 检查需求是否显式排除某个外壳功能；只有显式排除才裁剪，裁剪项记录在 Notes，其余保持模板原样。
6. 将业务页面放入 `Page Body Slot`，保留 Content 的 16px 间距。
7. 按业务上下文设置侧栏折叠、语言和 RTL 入口的状态；这些入口默认已存在，不做删除。
8. 检查 Header 左右分组是否对齐，以及长文案下是否发生遮挡或裁切。
9. 保存并重新打开文档，回读页面根 Frame、四项业务数据、Page Body Slot 与内部控件 `ref`；组件输入和 import 必须在保存后仍有效。

## 6. Sticky Note 说明

模板旁侧的 Sticky Note 是区域索引，不承载完整规范。每张便签只包含“区域名称 + 一句话职责”，并使用关联线和定位点连接到模板中的实际区域。

需要标注：

- 品牌区；
- Header（包含左侧页面位置和右侧全局操作）；
- 应用菜单；
- 内容间距；
- 页面内容槽。

关联线使用低强调度颜色，不遮挡关键文案；定位点必须落在所描述的区域内。Sticky Note 和关联线不属于最终页面。复制模板生成页面时可以不复制说明，但不得改变模板说明区和规范列出的固定约束。

## 7. 验收清单

- Header 使用 `Layout.Header → Flex → 左右内容组`。
- 模板具有独立标题、适用场景、功能说明和使用流程。
- 每张 Sticky Note 只描述一个区域，并通过关联线连接到正确位置。
- Sider、Menu、Breadcrumb、Select、Avatar 和图标均引用 Kit 内组件。
- Header 操作顺序正确，RTL 入口存在，用户区域结构完整且内容可替换。
- App Source Switcher 命名正确。
- 内容区保留 16px 外层间距，内部为白色直角容器。
- 页面仅替换 Page Body Slot，没有重复生成应用外壳。
- 页面根节点在保存后仍是可编辑的 App Shell Frame，Sider、Header、Content 与 Page Body 结构完整；内部可复用控件仍是当前 Kit 的 `antd:` 引用。仅有模板名称或元数据不通过。
- 所有页面壳的品牌名、Breadcrumb 第一级与已确认宿主系统名相同，Breadcrumb 第二级为模块；菜单树与需求导航一致，选中项正确；用户名为 `${宿主系统名}管理员`，头像不保留模板示例文字。
- 模板标注的外壳功能齐全；任何被移除的区域都能对应到需求中的明确排除说明，并已记录在 Notes。
- 1920 × 1080 基准下无裁切、溢出或缩放展示；长系统名下品牌、面包屑与右侧用户区不互相遮挡。
