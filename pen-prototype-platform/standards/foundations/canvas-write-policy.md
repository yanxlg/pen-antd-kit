# 画布写入策略：原型内容只能由 Pen MCP 生成

## 1. 规则

**原型的设计内容一律通过 Pen MCP（`execute`）生成和更新；禁止用代码读写 `.pen` 文件来产出或修改页面、弹窗、抽屉、面板及其内容。**

设计内容包括：

- 页面 / 抽屉 / 弹窗 / 面板 Frame 本身，以及它们的层级、命名、位置、尺寸；
- Frame 内的任何节点：文字、形状、组件实例、图标、图片、间距与样式；
- 交互态（加载、空、错误、禁用、发布中……）与注释；
- 对已有原型的任何修改——改文案、改列、加状态，都必须走 MCP，不能改文件。

判定标准很简单：**如果一次改动会改变画布上看得见的东西，它就必须经 MCP 发生。**

## 2. 为什么

- Pen 会把文件打开在内存里并持续写回；外部改文件与编辑器状态冲突，轻则被覆盖、重则让编辑器的文档服务卡死（本仓库实测过多次）。
- 编辑器只对它自己写出的节点形态负责：外部写进去的实例覆盖（`descendants`）会在保存时被剥离，外部写的相对 import 路径会静默丢 `inputs`。经 MCP 产生的节点不会有这些问题。
- 走 MCP 才有可回读的中间状态：每一步都能用 `Get`/截图验证，出问题能定位到具体调用。但 MCP 返回成功只证明内存中的编辑成功，不证明保存后仍持久化。实测最小 `ref` 作为导入 AppShell 内容槽的直接子节点可保存；同一个 Select `ref` 插入槽内现有 `Page Body / Filters Row` 的更深层级后会消失。因此必须按实际目标层级保存重开回读，不能推断所有嵌套层级的行为相同。

## 3. 允许的文件写入（唯一例外：bootstrap）

MCP 没有对应操作的事情，才允许由 CLI 写文件，且只写"脚手架"，不写设计：

| 允许 | 原因 |
| --- | --- |
| 创建空文档（`version/children/themes/variables`） | Pen MCP 没有"新建文档"操作 |
| 设置 `imports`（库的别名与路径） | `imports` 是文档级元数据，MCP 没有暴露写入接口 |

就这两样。**不通过文件写入模板、组件定义或 `Plan Notes`**：CLI 读取 Kit 模板并生成普通 Frame 的 MCP `Insert` 脚本；Frame 内可复用控件保持 `antd:<组件id>` 导入引用。`Plan Notes` 也是画布内容，同样由 MCP 生成。

除此之外的一切写入都算违规。bootstrap 的产物必须在执行报告里列出来（当前就是：文档容器 + `imports`）。

## 4. 执行顺序

```text
plan validate → doc build（写空文档 + imports）→ 打开文档 → 生成 execute 脚本 → 经 MCP 执行 → 回读校验
```

1. `pen-antd plan validate --plan <plan.json>`；`plan target` 给出输出路径。
2. `pen-antd doc build --plan <plan.json>`：CLI 只写空文档与 `imports`。
3. 由计划生成 `execute` 脚本：每个模板模块从 Kit 复制结构为普通 Frame，逐节点调用 `Insert` 创建层级；外壳 + 内容组合先在一页验证，保存重开后确认 Page Body 与内部组件 `ref` 仍存在；没有模板的模块插入占位 Frame 并写上结构清单；最后插入 `Plan Notes`。
4. 经 MCP 执行（默认每批 1 个模板模块；只有轻量模块才增大批次）：`pen-antd pen call --tool execute --args-file <script args>`。
5. 回读：保存并重开后，用 `Get(<节点 id>, {depth})` 检查根 Frame、内容区和内部组件的 `type/ref`，再用最小节点截图检查布局；**Pen 1.2.13 不支持全文档读取**，只能按已知 id 查。若候选组件消失，保留旧页面并停下，不得以手绘内容冒充完成。

## 5. MCP 不可用时

MCP 不可用是**阻塞**，不是降级理由：

- 先自检：`pen-antd pen call --tool get_style --args '{}'`；再看 `pen-antd pen tools`。
- 修复动作：退出 Pen 并重新打开（文档服务卡死时只有重启能恢复）；确认 `--app` 指向桌面版应用；确认没有残留的 mcp-server 进程占住连接。
- 仍然不可用时**停下来报告**，不要改用写文件的方式交付原型。诊断用的 `--via file` 只允许用于测试与故障排查，产出的文件不能当作交付物，也不得写入验收记录。

## 6. 验收

- 交付说明里能列出生成/更新原型用到的 MCP 调用（脚本与执行结果）；
- bootstrap 写入了什么有清单；
- 画布上的内容能通过 `Get`/截图回读到，且与计划一致；
- 若某个改动是直接改文件完成的，视为未交付。
