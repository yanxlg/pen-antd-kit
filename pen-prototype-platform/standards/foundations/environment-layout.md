# 环境、布局与视觉基础

## 1. 先确定承载环境

原型开始前必须标注页面由谁提供外壳：

- 嵌入宿主的微前端：宿主拥有登录、全局头部、一级导航、应用切换和最外层滚动。原型默认只画业务内容画布；需要展示上下文时，以灰色注释区表示宿主区域，不复制一套可交互导航。
- 独立应用：需求明确要求时才设计完整外壳，并保持所有页面一致；使用 `patterns/admin-app-shell.md` 规定的共享模板，不按页面重复绘制。
- 抽屉、弹窗和二级工作区：仍继承宿主的语言、方向、主题和权限语义。

不要因为输入 HTML 自带头部或侧栏，就默认把它们纳入业务页面。

## 2. 页面骨架

- 页面采用自然文档流，不把业务内容强行固定为 `100vh`。
- 宿主已经提供内容边距时，不再添加第二层相同外边距。
- 一级业务区块之间默认间隔 16px；同行控件和按钮默认间隔 8px；抽屉底部操作可使用 12px。
- 标准内容卡片使用中性容器背景、1px 次级边框、8px 圆角、16px 垂直与 20px 水平内边距。嵌套场景移除重复边框和内边距。
- 卡片标题建议 16px/600；标题、记录数和右侧操作形成一个清晰工具栏。记录数是辅助信息，不与主标题竞争。
- 优先使用 Ant Design token 表达颜色、圆角、阴影、字号和间距，不从历史页面复制孤立色值。

## 3. 密度与层级

- Ant Design 组件默认不设置 `size`，使用组件库的默认尺寸。只有需求明确要求紧凑密度、特定尺寸，或经确认的受限空间场景，才设置 `small`、`large` 等值。
- 不要为了塞入更多内容而全局改成紧凑尺寸；应先调整信息层级、列宽、换行和布局。一个连续操作区域内的同类组件必须保持一致尺寸。
- 每个页面只保留一个视觉主行动；次要行动使用默认按钮或文本行动。
- 查询区、数据区、编辑区必须有清楚的视觉边界，但避免“卡片套卡片”。
- 业务标识、代码和 URL 可用等宽字形；普通名称与说明使用正文样式。
- 状态用组件语义表达。颜色只能增强辨识，不能成为唯一线索。
- 真实内容要覆盖短值、长值、空值、数字 `0` 和布尔 `false`，不能把有效的 `0`/`false` 显示成占位符。

## 4. 目录 + 内容布局

- 左侧目录、右侧内容使用独立容器，间隔 16px；右侧必须 `min-width: 0`，避免表格撑破页面。
- 在固定 `1920px` 桌面页面内，左侧目录基线宽度 290px；不得为了额外制作窄屏状态而压缩目录或改变页面宽度。
- 长页面中目录可 sticky，且不得遮挡页面主行动。
- 目录项必须有选中、悬停、空结果和数量信息；使用语义化可点击项，当前项不仅靠颜色区分。
- 未选择目录时，内容区展示明确的选择提示，不发送依赖选中项的无效请求。

## 5. 国际化、RTL 与可访问性

- 语言和文字方向继承宿主，不在页面内自行维护另一份方向状态。
- 布局使用“起始/结束”语义；URL、代码等内容可单独保持 LTR。
- 至少用长英文或乌尔都语验证标题、标签、按钮和表头；不使用只适合短中文的固定宽度。
- 使用语义化 Button、Link、输入和标题；纯图标行动必须有可访问名称。
- 键盘焦点可见；校验失败后聚焦或滚动到第一个错误；浮层关闭后焦点返回触发点。
- Tooltip 只能补充信息，不能承载唯一说明或唯一操作路径。
